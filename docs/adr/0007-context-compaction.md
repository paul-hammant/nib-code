# Keep system stable; compact context at complete Step boundaries

**Decision:** New Sessions write cwd and original system in the first record of `$NIB_HOME/sessions/<32hex>.jsonl` (default `~/.nib/sessions/`). system concatenates base instructions, global AGENTS.md, then project AGENTS.md. Resume retains logged text; instruction changes affect new Sessions only. Subsequent history updates go through commit, appending logs, updating memory, and syncing. Commit a Step's assistant and all tool results together, including the user message for the first Step. Exclusive Session locks prevent concurrent resume; crashes' damaged tails are isolated by appending a newline and repair record without truncating the original file.

Check context before each Step and automatically compact at roughly 75% of the window; TUI `/compact` also requests manual compaction. Preserve system and preferably the latest two Turns, falling back to two complete Steps if one Turn is too long. Replace older content with one user summary followed by retained context; append a `from=1` replacement record, then continue appending Steps. Summary generation is limited to 1/8 of the window (minimum 32, maximum 2048 tokens). Estimated replacement context should fall to about half the window; without removable old Steps, issue a notice and skip. Invalid summaries, no reduction, or failure to reach half the window preserve original history and report errors; automatic compaction failure stops the current Turn.

Run results retain roughly 16 KiB total head/tail plus a truncation notice. This is roughly 4K English tokens, a byte-scale estimate rather than tokenizer measurement.

**Why:** Fixed system stabilizes request prefixes and isolates resume from instruction changes. Summary requests reuse old message prefixes and append summarization instructions to use caches, rather than re-encoding history as one large text block. The replacement prefix invalidates subsequent caches, so targeting half the window creates headroom before returning to append-only updates. A user summary avoids elevating model-generated content to system instructions. Complete Step boundaries preserve tool call/result pairing; recent verbatim context preserves work details. Append-only replacement records express new context without rewriting logs or introducing another store. Model context is resumable; external command/file effects are not rolled back.

**Sources and confidence (2026-11-01):** Primary source: `src/session.zig`, `src/session/log.zig`, `src/session/instructions.zig`, `src/tools.zig`, `src/main.zig`, `src/tui.zig`. Measured: unit tests verify replay matches in-memory safe points; mocks verify resume, automatic compaction in a 4096-token window, and TUI `/compact`. 75%, half, two Turns, and 2048 tokens are initial heuristics without real-model long-Session measurements. Summaries may lose detail; reported usage and byte estimates do not precisely predict the next request's tokens.

**Continue on failure (2026-11-01):** Automatic compaction is best effort. If it cannot reach half the window, or its request fails (except cancellation/out-of-memory), issue a notice and continue the Turn normally rather than failing it. After an ineffective summary request, wait for another 1/8-window growth before retrying, avoiding a summary request per Step. Fewer than three complete Steps does not back off, as one additional Step naturally resolves it. Manual `/compact` still reports errors. Measured locally with mocks: with a 1000-token window and system occupying nearly half, three consecutive Turns finished with only 2 summary requests.

**Codex summaries (2026-11-01):** Always use the current Session's model to reuse cached prefixes and avoid passing encrypted reasoning between models. Use none when reasoning can be disabled; pi marks gpt-6.1-sol/gpt-6-astra as unable to disable, so use minimum low. Codex does not reuse the small total-output limit: like pi, omit max_output_tokens and preserve normal server budgets. The original 32–2048-token budget constrains only summary text, leaving room for reasoning plus summary (pi catalog maxTokens 128000; backend determines actual quota). Empty summaries, incomplete/truncated responses, or ineffective compaction follow the notice-and-continue policy above; manual compaction errors. See [0011](0011-provider-wire-protocols.md) for protocol differences.

**When to reconsider:** Real long Sessions still exceed windows or compact repeatedly; omitted details cause errors; the latest two Steps no longer fit; model windows/output budgets change; or actual needs arise for restoring unfinished Steps, auditing every Tool side effect, or forking Sessions.
