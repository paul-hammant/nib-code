# 0017 Codex defaults to WebSocket with disposable continuation state

Codex Responses defaults to a Session-exclusive WebSocket to reuse connections and completed-response prefixes. Explicit SSE and Session-level fallback after handshake/frame-protocol failures remain available. Formal v7 benchmarks validated this configuration; 0.4.0 aligns binary defaults. Detailed experiments remain in adjacent `nib-speed-notes/`. Connection errors and response-field validation failures use WS retries, avoiding classification of one content error as permanent incompatibility.

Zig 0.17 has no standard-library WS client. A minimal RFC 6455 frame layer reuses `std.http.Client` TCP, proxy, TLS/certificates, and connection ownership. Sessions have only one main request at a time; no connection pool, warmup thread, or server-session storage is added. Send previous_response_id and incremental input only on the same connection, after prior completion, with matching non-input properties and history prefixed by previous input + ordered output. Background messages append afterward; waiting metadata stays off the wire.

Logs always store full history and ordered server output, without reconstructing prefixes from merged display text; this preserves interleaved reasoning/commentary, multiple messages, and custom/function calls. Continuation state is safely disposable after cancellation, disconnection, compaction, or scope changes; resume/fork do not copy connections. First requests, reconnects, and prefix changes therefore still send full history; correctness does not depend on server cache hits.

See [Codex transport](../codex.md#responses-websocket-传输) for protocol sources, limits, and local verification, and [logs](../session-log.md#step-传输字段) for per-attempt details and full-input reasons. Reconsider defaults if proxy/gateway incompatibility or fallback costs outweigh benefits; `NIB_CODEX_TRANSPORT=sse` falls back directly.
