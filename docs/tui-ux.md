# TUI task management and progress

Streaming redraws are paced from frame start at roughly 16 ms. The first assistant fragment is visible immediately; later bursts release a backlog-proportional share per frame against a 40 ms display deadline, on grapheme boundaries. Complete text enters the transcript and Session immediately. Ticks drain pending display text during server pauses. Interaction, retry, Run and Turn boundaries flush the display prefix. Reasoning stays hidden and Run arguments are unchanged. Completed Markdown lines cache layout by width; the active tail is reparsed as it grows. Waiting animations refresh at 100 ms; idle does not redraw.

`/tasks` makes no model requests and lists background agents, bash, and automatically backgrounded Runs registered in this process's current Session. Each row shows id, type, status, elapsed time, deadline, and a short description; an empty list shows a short message. Queued tasks wait for a definite deadline; once started, they use the tool's timeout. Deadlines show UTC hours/minutes/seconds and remaining seconds. Detached tasks show no deadline (explicit timeouts still execute in the tool). Runs have no wall-clock deadline and show `per-tool deadlines`; existing tool deadlines remain effective. Finished tasks' durations freeze.

`/stop <id>` is accepted immediately even during a Turn. The Session thread handles stopping, reusing tools.stop cancellation, join, and process-group cleanup; log `task_stop` records reason `user requested stop`. Completion warns that partial changes may remain. Finished tasks return already finished; unknown ids show errors. After `/stop `, the menu suggests active tasks by id prefix without model tool calls. Switching Sessions hides old tasks; resume does not restart processes.

Runs retain parent titles. Automatic backgrounding shows `Run · r3 running`; completion updates changes, tool summaries, and results in the original block. Superseded bash shows `b1 superseded by b2`, indicating neither validation pass nor failure. Parent titles flag child failures/timeouts without changing script return values. Hover highlights the summary rows of a Run, failure, background result or long user message. Click those rows to open or close only that block; Ctrl+O toggles the latest Run, background result or failure. A click is press and release on one cell; any drag selects instead. Toggling keeps the block's title on its screen row, and keeps following the bottom when the latest block is toggled. Opening shows Changes / Result / Script; full results scroll, and long diffs say `Diff preview · 60 of … lines`.

One blank line separates the activity line from the transcript, also during history browsing and temporary notices. Tighten spacing below 10 terminal rows or when body height is insufficient, preserving input. No extra row is reserved without an activity line.

The activity line names known phases: `Waiting for model`, `Thinking` (streaming reasoning), `Generating response` (visible text), `Writing Run`, `Running bash zig build test`, or `Waiting for r3 · 32s`. Turn time accumulates throughout. Nonempty reasoning, text, Run arguments, and task state/output progress reset the progress timer; heartbeats, metadata, usage, and elapsed time do not. After 30s without progress, show `no progress 30s`, without predicting an ETA. Normal activity is dim; retrying and no progress are yellow. History adds no activity text until content arrives, then shows `New output below`, preserved on narrow screens.

Retries show `Retrying · attempt 2/5 · rate limit`. Remove failed streamed drafts while preserving earlier answers and queued interjections. Leave one dim `Interrupted · retrying` line at the first removed draft until visible output arrives or the Turn finishes. Final failures show one sentence; hovering highlights its summary and opening it reveals the raw error. Cancellation keeps the draft and shows one recovery hint; unconsumed queued messages return to the editor with their count.

After Turn failure/cancellation, list files directly changed by edit/write in that Turn and `type continue to resume`; direct changes also prompt `/undo to revert edit/write`. Deduplicate paths by first change, including writes whose Run result has not returned; child-agent changes are not direct root-Session changes. If bash ran, say `bash changes untracked`; absent records show `no recorded edit/write changes`. Cancellation does not roll files back; the next ordinary input continues the Session context.

Recovery notices come only from the TUI, outside model history. `nib ask` (including non-TTY and NDJSON) adds no notices, preserving output channels and exit codes for scripts. `run_end` adds optional `background_id` to associate automatic background Runs; NDJSON event structure otherwise remains unchanged.

The bottom bar shows only the model and context percentage from existing usage reports; initially, only the model. Without usable credentials it shows `Not signed in` instead of a model, an empty transcript shows `No provider · /provider to sign in`. Turn footers show nonzero Run counts, Steps, total time, tokens, and tool data. Detailed model/Run timing and cache data live in `/status` (local, also available while running).

User messages use `›`, a blue accent, and subtle terminal-background-derived shading for light/dark themes. During drag selection, hold the left button and scroll across screens; release copies the complete historical range, including offscreen lines. Bottom following pauses during selection. See [undo.md](undo.md) for `/undo` scope and conflict handling.

`@` completes project paths. Typing `@` at the start of the input or after whitespace (not inside a word, so `a@b.com` is ordinary text, and not from a paste) opens the same menu as `/`, listing up to 8 files and directories below the working directory, skipping `.git` and .gitignore'd paths and credential files. Matches are case-insensitive on the relative path, ranked basename prefix, then path prefix, then subsequence, shorter paths first. Up/Down move, Tab or Enter accepts (Enter never sends while candidates are shown), Esc closes the menu only. A file inserts `@path` and a space; a directory inserts `@dir/` and keeps completing inside it. Paths with spaces are quoted: `@"my file.txt"`. The inserted text is ordinary editable text. Sending changes nothing: the message contains `@path` and the model reads files with its tools; no file contents are inlined and no prompt text is added.

The path listing is built on first use on a background thread, capped at 50k entries, and rebuilt when the menu opens if it is more than 5s old, so typing never waits on a large repository. Until the first listing arrives the menu stays empty.

`/provider` uses the same menu as `/`: one row per service with a status column, `current` on the active one, `Add endpoint…` last. Sending a message without credentials opens this menu pinned over the editor (Up/Down, Enter selects, Esc closes) and leaves the draft untouched. Steps that need text take over the input area and show their prompt in the activity line: an API key is typed as `•` per character, kept only in a wiped buffer, never in the draft, input history, transcript, or logs; Enter saves and Esc cancels with nothing written. The add-endpoint form asks name, base URL, key, protocol, then picks a listed model from a menu (or asks for the id) and a context window when the listing has none. Invalid answers show one error line and keep the step. Browser sign-in and model listing run on a background thread: Esc cancels, the activity line says `Waiting for ChatGPT sign-in` or `Listing models`, and a device code appears as `Open <url> and enter code <code>` in the transcript. Provider changes are blocked while a Turn runs like `/model`. Fixed texts: [ui-style.md](ui-style.md).

The framed input has exactly one blank row below its bottom border at heights of at least 8 rows. Well-known operations have no interface hints; `/help` lists keys. Necessary nib-specific entry points retain short hints. Protocol selection uses the standard menu, initially selecting OpenAI-compatible.
