# Session reflection and automatic issue publication

Reflection is available only with `NIB_ISSUE_REPO=owner/name`. Unset, empty, invalid, or `off` hides `/reflect` from the menu and help and treats it as an unknown command. Enabling it authorizes automatic publication with your own `gh` login.

Reflection: TUI `/reflect [focus]` asks the model to review harness friction, suggestions, and task-description problems against this session's logs (including child sessions), read-only. Normally completed answers append to `$NIB_HOME/reflections.md` (each headed with UTC time, session, cwd, model, and effort) for batch analysis and iteration. The final ```json drafts (at most 3) are then **automatically** published as GitHub issues without confirmation. The target repository is `NIB_ISSUE_REPO` (explicit owner/name; no default), using the user's own `gh` login and environment. Before drafting, the model checks open issues in the target repository with `gh issue list` and avoids duplicates with the same root cause. Before publication, titles are checked again for duplicates (existing issues are skipped), current project paths are replaced with `<project>` and HOME with `~`, and drafts resembling credentials (`sk-`, `ghp_`, `Bearer `, etc.) are withheld. Each result appears in the transcript and appends to reflections.md. Redaction is only a fallback; the prompt's requirement to exclude project content is the primary protection. The prompt template is `src/tui/reflect.md` (embedded at compile time; edit wording there), with placeholders `{{session_id}}`, `{{log_path}}`, `{{issue_repo}}`, and `{{focus}}`. Reflection answers and issue titles/bodies are in English.
