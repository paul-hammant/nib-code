# 保持 system 稳定，按完整 Step 压缩上下文

**决定：** 新会话把 cwd 和原始 system 写入 `$XDG_DATA_HOME/nib/sessions/<32hex>.jsonl` 的首条记录。system 按基础指令、全局、项目 `AGENTS.md` 的顺序拼接；恢复沿用日志中的原文，新指令文件只影响新会话。后续模型历史统一通过 commit 追加日志、更新内存并 sync；一个 Step 的 assistant 与全部 tool 结果一起提交，首步还包括用户消息。一个会话由独占锁保护，不能同时恢复；崩溃留下的损坏尾部通过追加换行与 repair 记录隔离，不截断原文件。

每个 Step 前检查上下文，约达窗口的 75% 时自动压缩；TUI 也可用 `/compact` 手动请求。保留 system，优先保留最近两轮；单轮过长时退到最近两个完整 Step。较早内容变成一条 user 摘要，随后接保留的上下文；日志追加 `from=1` 的替换记录，之后继续追加 Step。摘要生成上限为窗口的 1/8（最低 32、最高 2048 tokens）；替换后预估上下文需降到窗口约一半，若没有可裁剪的旧 Step，则提示 notice 并跳过；摘要无效、未缩小上下文或未达到半窗口目标时保留原历史并报错，自动压缩失败时当前 Turn 随之停止。

Run 返回结果保留首尾合计约 16 KiB，另加截断说明。约相当于 4K 英文 tokens，只是字节量级估计，不是 tokenizer 的测量结果。

**为什么：** 固定 system 保持请求前缀稳定，也让恢复不受指令文件改动影响。摘要请求复用旧消息前缀、末尾追加总结指令，利用已有缓存，避免把历史再编码成一大段文本。摘要写回后的新前缀会使后续缓存失效，因此以半窗口为目标腾出较大余量，之后恢复只追加。把摘要放在 user 消息中避免把模型生成的内容升格为 system 指令。完整 Step 边界保留 tool call/result 配对；近期原文保留当前工作细节。日志用追加替换记录表达新上下文，无需改写旧日志或引入第二种存储。模型上下文可恢复，外部命令和文件副作用不随之回滚。

**事实来源与把握程度（2026-11-01）：** 一手源码：`src/agent.zig`、`src/log.zig`、`src/instructions.zig`、`src/tools.zig`、`src/main.zig`、`src/tui.zig`。实测：单元测试验证重放等于内存安全点，mock 验证恢复、4096-token 窗口下的自动压缩与 TUI `/compact`。75%、一半、两轮与 2048 tokens 是初始启发式，尚无真实模型长会话实测；摘要可能丢失细节，模型报告的 usage 与字节估算也不等于下一请求的精确 token 数。

**失败时继续（2026-11-01）：** 自动压缩只尽力而为。压缩不能把上下文降到半窗口以下，或摘要请求本身失败（取消和内存不足除外）时，发一条 notice，然后照常继续当前 Turn，不再让 Turn 失败。发出过摘要请求却没有效果时，等上下文再增长窗口的 1/8 才重试，避免每个 Step 都花一次摘要请求。"完整 Step 不足三个"不退避，因为再完成一个 Step 就会自然解决。手动 `/compact` 仍会报告错误。实测：窗口设为 1000、system 占近一半时，连续三轮都正常完成，只发了 2 次摘要请求（本地 mock）。

**何时重新考虑：** 真实长会话在压缩后仍超窗、反复压缩，或摘要遗漏导致错误；近期两个 Step 已无法容纳；模型窗口或输出预算改变；出现需要恢复未完成 Step、审计全部 Tool 副作用或分叉会话的实际需求。
