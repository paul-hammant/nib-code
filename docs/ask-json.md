# ask 的 NDJSON 接口

`nib ask --json '<prompt>'` 的 stdout 是 NDJSON：每行一个单键对象，按产生顺序输出并立即 flush；stderr 没有人类可读进度或颜色。prompt 为 `-` 时从 stdin 读到 EOF（普通 ask 也支持）。退出码成功 0，失败非 0。

- `{"start":{"session_id":"<32位小写十六进制>"}}`：Session 已初始化；恢复时沿用原 id。
- `{"step":{"n":3,"effort":"low","source":"model"}}`：每次主模型 Step 请求开始前发送；`n` 在每个 Turn 内从 1 开始，`effort` 是通过护栏后的实际请求档位，未指定服务端档位时为 `default`。`source` 为 `model|default|guard`：模型声明生效、用户默认（含显式恢复 default）、声明被护栏回退。重试不重复发送，压缩请求不产生 Step 事件。随后的所有 `run_start/run_end` 属于该 Step，直到下一个 step 事件。普通 ask 不显示；TUI 保留相同元数据，默认 Run 标题不显示 effort。
- `{"delta":{"kind":"text|reasoning","text":"..."}}`：模型流式片段，包含中间 Step 的文本。存在待交付的普通后台任务时，text 暂存到响应完成：带工具的回复再发出 text delta；无工具的等待回复改为 notice，不发 text delta。最终答案仍只取 end.text。
- `{"run_start":"<JS代码>"}`、`{"run_end":{"ok":true,"output":"...","changes":[...],"tool_summary":{"counts":[{"name":"read","count":2},{"name":"bash","count":1}],"omitted":0,"files":[{"tool":"read","path":"src/a.zig"}]}}}`：一次 Run 的开始和结果；`run_start` 保持字符串格式，不加入 effort，产生该 Run 的请求档位取前一个 `step` 事件。Run 失败可由模型继续处理。`changes` 列出这次 Run 里成功 edit/write 的累计改动：`{"path","added","removed","created","diff"}`。每次操作成功时比较其紧邻的 before/after 内容，同路径 added/removed 求和、created 取逻辑或，路径保持首次出现顺序；不是 Run 起止内容的净 diff，改后又撤销会计入两个方向。失败的工具调用不贡献改动，但 Run 后续失败不撤销此前成功调用的记录。`diff` 按操作顺序拼接带一行上下文的 `+`/`-`/` ` 行，操作之间用 `…` 分隔；每路径整个 Run 最多展示 200 行改动/上下文，省略标记不计入该额度，计数不受预览截断影响。Run 结束时不重新读盘；bash、外部进程和子会话（含后台任务）在两次写入之间或最后一次写入之后的改动都不归入当前 Run，但在后续 edit/write 的 diff 中可能作为未改动的上下文出现。`tool_summary` 是本次 Run 实际调度的宿主工具汇总，按工具名首次实际调度的顺序列出 `counts: [{name, count}]`；包含调度后返回错误的调用，不包含准入拒绝（例如超限的 llm）或子会话内部调用，也不从 JS 源码推测。底层 Step 级 timing 最多保留 200 条调用记录，`omitted` 是本次 Run 超出记录上限的条数，不能归属到具体工具名，因此溢出时 `counts` 不是完整计数；超限后未保留的准入拒绝也可能计入 `omitted`。正常发出的 `run_end` 总带此对象，即使没有工具调用也为 `{"counts":[],"omitted":0,"files":[]}`；兼容旧事件的可选字段缺失表示没有汇总，不能视为零调用。`files` 是实际派发的 read/grep/glob 的去重 `{tool,path}`，沿首次派发顺序；旧日志可缺省。它只供界面列出路径，不改变工具返回值，也不发送给模型。
- `{"progress":{"id":"a1","background":false,"kind":"agent","run":1,"prompt":"检查测试","state":"working","step":3,"tools":["edit"],"files":["src/x.zig"],"usage":{"prompt_tokens":41000,"completion_tokens":200,"prompt_cache_hit_tokens":32000}}}`：工具任务的最新进度快照。`id` 是会话级任务编号：前后台 agent 共用 `a1、a2…`，bash 独立使用 `b1、b2…`，跨 Run/Turn 不重置，恢复时分别接着日志中各前缀的最大值。`background` 标识后台任务，其 `id` 与启动返回的 `{id}`、`background` 事件和结果消息一致；不再提供旧的 `agent` 或 `background_id` 字段。`detached` 默认为 false，标识正常 Turn 不等待的后台 bash。`run` 是 Session 内从 1 开始的发起 Run 编号（包含 `/js`），进度用它关联原 Run。`kind` 为 `agent|bash`；bash 的 `prompt` 为完整命令、`elapsed_ms` 为已运行毫秒数，所有 bash 在启动时分配 id；前台 bash 超过 3 秒才显示运行中进度，此后约每秒更新；所有命令结束时都产生终态进度，正常退出时带 `exit_code`。agent 的 `prompt` 是完整子任务提示词；`state` 为 `queued|working|done|failed|canceled|timed_out`，TUI 将内部 working/done/timed_out 映射为 running/completed/timed out。后台任务已结束但结果未送达时显示 waiting，已知失败或超时立即提示；detached 另作标注。`step` 从 1 开始，尚未收到模型活动时为 0；`tools` 是最近一次 `run_start` 代码中识别出的去重 `tools.<name>(...)` 调用名称，`files` 是该次 `run_end.changes` 的文件路径（新 Run 开始时清空）；`usage` 是这个子 agent 已报告的累计用量，显示 token 时取 prompt + completion，不重复加缓存 token。不是 token 增量，也不额外计入父会话用量。同一任务的常规事件至少间隔一秒，中间状态合并为最新快照，终态不等待节流；最终结果/用量以 `run_end` 和 `end/error` 为准。普通 ask 不显示此事件。 接续 agent 沿用原任务 id。`invocation` 是宿主用于区分同一 id 各次调用的进度元数据，不是任务 id，不进入 `tools.agent` 参数/结果或状态树文字；0 表示未分配此元数据，恢复会话不保留该序号。
- `{"background":{"id":"a1","kind":"agent","state":"started"}}`、`{"background":{"id":"b2","kind":"bash","state":"finished","ok":true}}`：后台 agent/bash 生命周期。两类任务分别使用 `a`、`b` 计数器，与 progress 的 `id` 一致；`started` 在启动前同步写入日志后发送，`finished` 在结果插入主会话时发送，恢复未完成任务时发送 `lost`。`ok` 仅随 `finished` 提供；事件不带结果正文。普通 ask 不显示此事件。
- `{"usage":{"prompt_tokens":0,"completion_tokens":0,"prompt_cache_hit_tokens":0}}`：本轮累计用量快照（含已报告的子会话用量），不是增量；用于中途显示与强制终止后的统计。
- `{"retry":{"attempt":1,"delay_ms":1000,"reason":"..."}}`、`{"notice":"..."}`：重试与通知。
- `{"end":{"text":"<最终回答>","usage":{"prompt_tokens":0,"completion_tokens":0,"prompt_cache_hit_tokens":0},"steps":1}}`：Turn 成功结束；usage 只统计本轮，含自动压缩和子会话。最终回答取这里的 text，不拼接所有 delta。
- `{"error":{"message":"...","usage":{"prompt_tokens":0,"completion_tokens":0,"prompt_cache_hit_tokens":0},"steps":0}}`：命令或 Turn 失败，没有 end；初始化失败时可能没有 start。usage/steps 保留失败前已报告的统计。错误文本供诊断，不作为稳定错误码。

`end` 和 `error` 还可带 `timing: {wall_ms, model_ms, run_ms, llm_calls, agent_calls, tool_bytes, output_bytes}`。开始执行 Turn 后总会提供；命令解析或 Session 初始化失败、尚未开始 Turn 时省略。`wall_ms` 是整个 Turn 的单调墙钟耗时（含失败或取消前的等待、压缩和清理），`model_ms`、`run_ms` 分别是本轮已提交完整 Step 的同名日志字段之和，不包含未完成 Step；`llm_calls`、`agent_calls` 是这些 Step 内实际调度的宿主工具调用数，含返回错误的调用，不含子会话内部调用，不受日志 `calls` 的 200 条上限影响。`tool_bytes`、`output_bytes` 也是本轮已提交完整 Step 的同名日志字段之和：前者为宿主交给 JS 的工具结果字节数（成功按序列化 JSON、错误按错误文本计 UTF-8 字节），后者为 Run 格式化后交给模型的 tool result 实际 UTF-8 字节数（含截断标记、错误、无输出提示和标签等），加上各完整 Step 请求前新插入的后台 agent/bash 结果消息正文的 UTF-8 字节数（含后台消息前缀、换行和截断标记；不含用户插话，不重复统计历史消息）。未完成 Step 不计入，agent 只计父 Run 返回对象，不累加子会话内部工具数据；与 `TurnSummary.timing` 口径一致。计时单位为毫秒，字节和调用计数为 0 时仍保留键。原有 `usage/steps` 口径不变，因此失败时可能包含未完成 Step 已报告的用量。普通 ask 不输出这组计时；Session 内部的 `turn_end` 快照不会作为额外 NDJSON 事件发出。

事件结构与序列化定义在 `src/session/events.zig`。字符串中的换行经过 JSON 转义，每个物理行都是完整 JSON。

会话提交与取消语义见 [session-log.md](session-log.md)，子会话调用约定见 [tool-delegation.md](tool-delegation.md)。

自动后台 Run 使用 `background.kind:"run"` 和 `rN` ID。提前 `run_end` 的 output 是转后台通知、changes 为空，ok 只表示通知成功；最终 `background.state:"finished"` 的 completion 含原 step/run_index、实际 ok、配置预算内（默认 16 KiB）的 output、完整 run_ms/tool_bytes/calls/calls_omitted/changes 及实际执行区间 execution。该事件不产生第二个 run_end。具体字段与计量见 [session-log.md](session-log.md#自动后台-run-的记录与统计)。

后台 bash 的 finished 事件可带 `execution:{start_ms_epoch,end_ms_epoch}`（Unix 毫秒，spawn 前至 wait 完成）；结束时间早于或等于结果送达时间。未成功启动进程时省略。自动后台 Run 的 completion.execution 从原 Run 创建时开始，包含自动切换前等待。

TUI 的恢复提示不写入 ask 输出。自动转后台的 `run_end` 可带 `background_id`（如 `r3`），`ok:true` 此时仅表示成功登记；最终状态取后台结果。bash 的 progress 可带 `superseded_by`，取代是中性状态；`output_bytes` 是已观察到的命令输出进度，用于区分实际输出和纯计时心跳。
