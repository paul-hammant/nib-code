# UI style

For agents changing the TUI, CLI help, or fixed text.

- Use English for fixed UI text; preserve the language of model output. Derive titles from tool summaries, diffs, exit codes, and task events; do not add model output or prompt requirements for the UI.
- Run is the stable parent block. The collapsed layer shows factual summaries, file changes, command results, and task status; expand in Changes / Result / Script order. Explicitly label omitted content as a preview and state its scope.
- No hints for well-known operations: Enter sends or saves/selects, Esc cancels/closes, PgUp/PgDn scroll, and clicking a highlighted block. Keep short hints for necessary nib-specific entry points users could not otherwise discover, especially `No provider · /provider to sign in` when signed out. When in doubt, keep a nib-specific hint. Show interactivity with subtle, background-derived hover highlights; `/help` lists keys. Collapsed blocks toggle from all summary rows; expanded details remain selectable. Ctrl+O targets the latest Run, background result or failure.
- Status words: queued / running / waiting / completed / failed / canceled / timed out / superseded / lost. Map internal enums to display text; do not treat the JS return value `ok` as task completion status.
- Use singular/plural counts: 1 step, 2 steps, 1 Run, 2 Runs, 1 file, 2 files. Write shortcuts as Enter, Shift+Enter, Esc, Ctrl+O, Ctrl+C, PgUp, PgDn.
- Round time down to seconds: <1s, 24s, 1m40s, 1h0m0s. Abbreviate numbers with decimal k/M, at most one decimal place (rounded down, no trailing .0); specify tokens, B, kB, MB. Share `src/tui/format.zig`.
- Separate fields with `·`; use `→` only for data direction. `✓` confirms completion only of the explicitly named adjacent object; `✗` means failure. Use terminal yellow and explicit status for timeouts, lost tasks, and items needing inspection; red for failures, muted colors elsewhere where possible. Use native terminal colors.
- Success is quiet; deviations stand out. The activity line states known facts, accumulating time throughout the Turn; show end-of-Turn statistics once, omitting zero values. Put detailed timing and cache data in /status.
- Images are atomic editor blocks labeled exactly `[Image #N]`, numbered with paste blocks. Notices (dim, until the next key): `<model> has no image input`, `<name>: unsupported image: expected png, jpeg, gif or webp`, `<name>: image is larger than 5 MB`, `No clipboard image tool · install wl-paste or xclip`, `No image in clipboard`, `Clipboard image is larger than 5 MB`, `Turn running · images send with the next message`. Many terminals intercept Ctrl+V and send an empty (or whitespace-only) bracketed paste when the clipboard holds only an image; that paste reads the clipboard image exactly like Ctrl+V, so an empty clipboard shows `No image in clipboard`. The clipboard tool is killed after 2 seconds and counts as no image. Run blocks show `view <path> · <width>×<height>` like read lines.
- Check layouts at 60 / 120 / 160 columns; truncate menus and single-line previews with `…`, preserving UTF-8 grapheme boundaries. The display budget does not affect tool data returned to JS.

- Sent user messages carry no prefix: `▎ text`, with the terminal blue (index 4) left `▎` accent; `›` appears only as the input prompt. Leave body text in the default foreground without bolding the whole message. Blend 1/8 blue into the terminal-reported background for light/dark themes; query again on theme changes. Without color reports, keep the default background and blue accent. Collapsed and queued markers remain muted.
- Show read/search path details and Run titles in only one place: when actual paths exist, keep details and omit corresponding tool names from the title; without path metadata, show tool names and counts. Omit Step numbers from the activity line; put Step counts in the Turn footer and /status.
- Keep `/undo` messages short and English, explicitly scoped to edit/write. If snapshots fail or exceed limits, explain that the Turn cannot be fully undone; editing continues normally. Recovery messages after failure/cancellation may suggest `/undo`, without implying that bash side effects can be undone.
- Layout: the framed input sits flush with the last terminal row. Exactly one status row is always reserved directly above the input (above the `/` menu when open): it holds the activity line and is blank otherwise, so the input never moves. The bottom border shows ` <model> · context N% ` with one space on each side of the text. Below 8 rows the status row exists only while it has text.
- Activity phases use `Waiting for model`, `Thinking` (streaming reasoning), `Generating response` (visible text), and `Writing Run` (Run arguments). Normal activity is dim; retrying and no progress for at least 30s are yellow. History is silent until new content arrives: `New output below`. A removed retry draft leaves `Interrupted · retrying` until visible output or Turn completion.
- Provider texts: bottom bar `Not signed in`; empty transcript `No provider · /provider to sign in`; menu status column `signed in · ChatGPT Plus`, the key's environment variable name, `key stored`, a host, or `—`, and `· current` on the active service; last menu row `Add endpoint…`. Activity-line steps state facts: `<Service> API key`, `Add endpoint 1/4 · Name` … `4/4 · Protocol`, `Add endpoint · Model id`, `Add endpoint · Context window · default 128000`, `Choose a model`, `Choose a service`, `Waiting for ChatGPT sign-in`, `Listing models`. Results are single lines naming the object: `Codex · signed in · ChatGPT Plus`, `openai · gpt-6.1-sol`, `Anthropic · signed out · key still set in ANTHROPIC_API_KEY`, `Codex · signed out · Codex CLI login kept`, `Could not list models · type the model id`. `nib ask` without credentials: `No provider · run nib login`. Never print a key; show it only as `•`.

Changes line: below the Turn footer after a successful Turn with direct edit/write changes, dim, normal mode only: `3 files changed · +42 −7`, singular `1 file changed`, zero `+`/`−` parts omitted. Opened, it adds one row per file indented two spaces: path relative to the working directory, then counts with `+` right-aligned and `−` after it (`  src/tui.zig  +30 −4`). It is a toggle block: hover highlight, click and Ctrl+O as for Runs.

Title line: an empty transcript shows dim `<project> · <branch> · <model> · <effort>` at its top-left (`nibcode · main · deepseek-flash · high`); the branch part is omitted without git, the effort part when the server picks it. Signed out shows `No provider · /provider to sign in` instead.

Open command (only with `open` configured): paths that resolve to project files look like normal text and are underlined while hovered. A failed start shows the dim notice `Could not run <program>`.

Hooks: successful commands are silent. After-edit failure adds one warning-colored line in the Run block: `hook <command> · exit <code>`. Turn-end failure adds a dim notice: `hook turn_end · exit <code>`. `/status` adds `Hooks: after_edit <count> · turn_end <count>` only when any hooks are configured.

Input prediction: after a root Turn ends normally, a background request (the user's last 8 typed messages, each cut to 300 bytes and capped at 3 KB in total, plus the tail of the last reply) predicts the next message and shows it as dim ghost text in place of the placeholder (also in Simple mode), only while the editor is completely empty. Tab inserts it (Enter sends); typing hides it, clearing shows it again. It is dropped when the next Turn starts, on `/compact`, `/new`, `/resume` and model or provider changes; late results are discarded by generation. Failures, timeouts and empty, `NONE`-style "no reply" or thanks-only replies show nothing, with no notice or status text.

## Typography and color

Assistant Markdown stays plain and quiet: three emphasis levels (bold, normal, dim), one accent color.

- Accent: terminal blue (index 4), used only for the user message bar `▎`, headings, the input prompt `›`, and selection/focus. Red, green and yellow mean state only (failure, success, warning, diff −/+). Nothing else in the transcript is decorated with color, except strings in tagged code blocks (cyan, below).
- Paragraphs: outside code, a blank source line or a single newline between two prose lines is a paragraph break, rendered as exactly one blank row (runs of blank lines collapse). No blank row is added inside lists (including continuation lines), quotes, tables or code, and none at the very top or bottom of a message.
- Headings: bold blue without the `#`, one blank row above (not for the first line of a message), none below.
- Inline code: normal foreground on a neutral background tint. Code blocks: normal foreground (plus the syntax marks below) on the same tint across the full width with one space of padding on each side; the fence and its info string are not shown. The tint is the terminal background shifted by 10 per RGB channel (lighter on dark, darker on light), so it stays subtler than the user-message shade. Without a background report there is no tint: inline code is plain text and code blocks keep a dim `│ ` bar.
- Syntax in code blocks: a fence tagged `zig`, `js`/`javascript`/`ts`/`typescript`/`jsx`/`tsx`, `python`/`py`, `sh`/`bash`/`shell`/`zsh`/`console`, `rust`/`rs`, `go`, `c`/`h` or `cpp`/`c++` gets three marks and nothing else (no numbers, types or function names): comments dim, strings and char literals in terminal cyan (palette index 6, which each terminal scheme keeps readable on light and dark backgrounds and which no other element uses), keywords bold. Untagged and unknown tags, and inline code, stay plain. A small per-line lexer (`src/tui/syntax.zig`) carries block comments, Python triple quotes, JavaScript/Go backtick strings across lines and treats Zig `\\` lines as strings; a quote that does not close on its line, Rust lifetimes, `#include` lines and shell `#` inside a word are plain. Token boundaries never split a grapheme cluster. Streaming reparses the unfinished tail; finished lines are cached with their starting lexer state.
- Diff lines in an opened Run: `+` green, `−` red, context dim. When a run of `-` lines is directly followed by a run of `+` lines with the same count, lines are paired by position and the part between their common prefix and suffix (on grapheme boundaries) is bold. No emphasis for unequal runs, empty lines, identical lines, or when the changed part is more than 60% of the longer line (basically rewritten).
- Italic `*text*` / `_text_` (not inside words for `_`) renders italic with hidden markers. Links `[text](url)` render the text followed by a dim ` (url)`; bare URLs are unchanged. Quotes `> text` render a dim `│ ` bar and normal text. Lists are unchanged.
- Run and background-result titles (`Run · edit 2 files · bash`) use the normal foreground; status marks keep their colors. The summary lines below (changed files, reads, bash lines, agent tree) are dim. Expanded details are unchanged.

### Tables

A pipe table (header row, delimiter row such as `|---|:---:|---:|`, body rows; outer pipes optional) outside code renders without pipes: dim header cells (not bold, inline styles kept), no rule row, body rows in normal style. Columns are aligned by terminal display width (CJK counts 2) with 2 spaces between columns; `:---`, `---`, `:---:` and `---:` select left, left, center and right alignment. Cells keep inline styles (`code`, **bold**, italic, links); `\|` shows as `|`. Short rows are padded with empty cells and extra cells are ignored. A table with more than 16 columns, or wider than the available width, is shown as the original lines (never truncated or wrapped). A line containing `|` without a valid header and delimiter pair is ordinary text, and tables inside code fences are untouched. A table block ends at a blank line or a line without `|`.

Streaming: once the header and delimiter rows are complete the table renders aligned, and the whole block is laid out again as each row arrives (column widths may grow). The finished-line cache keeps a table out until a terminated line after its last row closes the block, and a possible header line stays out until the next line is known. Mouse selection copies the screen text; `/copy` returns the original Markdown.

## Simple mode

`/simple` or Ctrl+S toggles a persisted reading mode without a notice, including during a Turn. Normal mode is the default. Kitty binds Ctrl+Shift+S to paste-from-selection by default; use Ctrl+S there. Ctrl+Shift+S also toggles Simple mode when delivered distinctly by the terminal. Raw mode disables IXON so Ctrl+S does not freeze output. `/help` lists `Ctrl+S simple mode`.

Simple mode hides Turn footers; `/status` retains all details. Width, margins, turn spacing and the bordered input box match Normal mode, including the input flush with the last row. The input has no placeholder. Its bottom border is always plain; at 80% context usage or above a dim ` context N% ` is right-aligned inside the corners of the top border.

The signed-out hint, activity, menus, provider flows, notices, errors and warnings remain available.

Collapsed Runs use one title line: successful Runs carry no mark (success is silent); failures and warnings keep their red ✗ / yellow ! marks; running Runs keep their live text. Running agent trees remain visible to preserve progress. Opening retains normal summaries and details. User shading and Markdown are unchanged.

Hover shifts each reported background RGB channel by +18 on dark backgrounds or −18 on light backgrounds (saturated). Without a background report, a reported dark scheme uses RGB 18/18/18 and light uses 237/237/237. Without either report, hover adds no background. This neutral shade stays restrained beside the blue user-message tint.
