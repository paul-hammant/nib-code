# UI style

For agents changing the TUI, CLI help, or fixed text.

- Use English for fixed UI text; preserve the language of model output. Derive titles from tool summaries, diffs, exit codes, and task events; do not add model output or prompt requirements for the UI.
- Run is the stable parent block. The collapsed layer shows factual summaries, file changes, command results, and task status; expand in Changes / Result / Script order. Explicitly label omitted content as a preview and state its scope.
- No hints for well-known operations: Enter sends or saves/selects, Esc cancels/closes, PgUp/PgDn scroll, and clicking a highlighted block. Keep short hints for necessary nib-specific entry points users could not otherwise discover, especially `No provider · /provider to sign in` when signed out. When in doubt, keep a nib-specific hint. Show interactivity with subtle, background-derived hover highlights; `/help` lists keys. Collapsed blocks toggle from all summary rows; expanded details remain selectable. Ctrl+O targets the latest Run, background result or failure.
- Status words: queued / running / waiting / completed / failed / canceled / timed out / superseded / lost. Map internal enums to display text; do not treat the JS return value `ok` as task completion status.
- Use singular/plural counts: 1 step, 2 steps, 1 Run, 2 Runs, 1 file, 2 files. Write shortcuts as Enter, Shift+Enter, Esc, Ctrl+O, Ctrl+C, PgUp, PgDn.
- Round time down to seconds: <1s, 24s, 1m40s, 1h0m0s. Abbreviate numbers with decimal k/M, at most one decimal place (rounded down, no trailing .0); specify tokens, B, kB, MB. Share `src/tui/format.zig`.
- Separate fields with `·`; use `→` only for data direction. `✓` confirms completion only of the explicitly named adjacent object; `✗` means failure. Use terminal yellow and explicit status for timeouts, lost tasks, and items needing inspection; red for failures, muted colors elsewhere where possible. Use native terminal colors.
- Success is quiet; deviations stand out. The activity line states known facts, accumulating time throughout the Turn; show end-of-Turn statistics once, omitting zero values. Put detailed timing and cache data in /status.
- Images are atomic editor blocks labeled exactly `[Image #N]`, numbered with paste blocks. Notices (dim, until the next key): `<model> has no image input`, `<name>: unsupported image: expected png, jpeg, gif or webp`, `<name>: image is larger than 5 MB`, `No clipboard image tool · install wl-paste or xclip`, `No image in clipboard`, `Clipboard image is larger than 5 MB`, `Turn running · images send with the next message`. Run blocks show `view <path> · <width>×<height>` like read lines.
- Check layouts at 60 / 120 / 160 columns; truncate menus and single-line previews with `…`, preserving UTF-8 grapheme boundaries. The display budget does not affect tool data returned to JS.

- Keep the `›` prefix on user messages; use terminal blue (index 4) for the prefix and left `▎` accent, leaving body text in the default foreground without bolding the whole message. Blend 1/8 blue into the terminal-reported background for light/dark themes; query again on theme changes. Without color reports, keep the default background and blue accent. Collapsed and queued markers remain muted.
- Show read/search path details and Run titles in only one place: when actual paths exist, keep details and omit corresponding tool names from the title; without path metadata, show tool names and counts. Omit Step numbers from the activity line; put Step counts in the Turn footer and /status.
- Keep `/undo` messages short and English, explicitly scoped to edit/write. If snapshots fail or exceed limits, explain that the Turn cannot be fully undone; editing continues normally. Recovery messages after failure/cancellation may suggest `/undo`, without implying that bash side effects can be undone.
- Activity phases use `Waiting for model`, `Thinking` (streaming reasoning), `Generating response` (visible text), and `Writing Run` (Run arguments). Normal activity is dim; retrying and no progress for at least 30s are yellow. History is silent until new content arrives: `New output below`. A removed retry draft leaves `Interrupted · retrying` until visible output or Turn completion.
- Provider texts: bottom bar `Not signed in`; empty transcript `No provider · /provider to sign in`; menu status column `signed in · ChatGPT Plus`, the key's environment variable name, `key stored`, a host, or `—`, and `· current` on the active service; last menu row `Add endpoint…`. Activity-line steps state facts: `<Service> API key`, `Add endpoint 1/4 · Name` … `4/4 · Protocol`, `Add endpoint · Model id`, `Add endpoint · Context window · default 128000`, `Choose a model`, `Choose a service`, `Waiting for ChatGPT sign-in`, `Listing models`. Results are single lines naming the object: `Codex · signed in · ChatGPT Plus`, `openai · gpt-6.1-sol`, `Anthropic · signed out · key still set in ANTHROPIC_API_KEY`, `Codex · signed out · Codex CLI login kept`, `Could not list models · type the model id`. `nib ask` without credentials: `No provider · run nib login`. Never print a key; show it only as `•`.

Hooks: successful commands are silent. After-edit failure adds one warning-colored line in the Run block: `hook <command> · exit <code>`. Turn-end failure adds a dim notice: `hook turn_end · exit <code>`. `/status` adds `Hooks: after_edit <count> · turn_end <count>` only when any hooks are configured.

## Simple mode

`/simple` or Ctrl+S toggles a persisted reading mode without a notice, including during a Turn. Normal mode is the default. Kitty binds Ctrl+Shift+S to paste-from-selection by default; use Ctrl+S there. Ctrl+Shift+S also toggles Simple mode when delivered distinctly by the terminal. Raw mode disables IXON so Ctrl+S does not freeze output. `/help` lists `Ctrl+S simple mode`.

Simple mode hides Turn footers and bottom-border metadata; `/status` retains all details. A dim full-width `─` separator replaces the input box, with `›` before the input, no placeholder, and exactly one blank row below. At 80% context usage, a single dim `context N%` appears right-aligned on the separator. The signed-out hint, activity, menus, provider flows, notices, errors and warnings remain available.

Above 110 columns, the reading column is 100 columns wide and centered; narrower terminals use full width. An extra blank row separates turns. Collapsed Runs use one title line: successful Runs carry no mark (success is silent); failures and warnings keep their red ✗ / yellow ! marks; running Runs keep their live text. Running agent trees remain visible to preserve progress. Opening retains normal summaries and details. User shading and Markdown are unchanged.

Hover shifts each reported background RGB channel by +18 on dark backgrounds or −18 on light backgrounds (saturated). Without a background report, a reported dark scheme uses RGB 18/18/18 and light uses 237/237/237. Without either report, hover adds no background. This neutral shade stays restrained beside the blue user-message tint.
