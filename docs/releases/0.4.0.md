# nib 0.4.0

这一版减少长命令和模型请求中的等待，让 nib 更适合日常开发；默认配置与已验证的 v7 一致。

## 默认行为变化

- **Codex 默认 WebSocket**：同 Session 复用连接，满足前缀条件时只发送新增输入；握手或协议失败后本 Session 自动降级 SSE。强制使用旧传输可设 `NIB_CODEX_TRANSPORT=sse`。
- **Codex 默认 custom Run**：模型直接生成 JavaScript，减少 JSON 字符串转义。设 `NIB_CODEX_RUN_TOOL=function` 可回退；历史调用保留原类型，恢复时不转换已有记录。
- **默认关闭可读推理摘要**：推理 effort 和加密 reasoning 延续不变；需要显示摘要时设 `NIB_REASONING_SUMMARY=auto`。
- **普通 bash 默认超时 30 分钟**：前台和显式后台相同，自动转后台不重置截止时间；可显式传 `timeout_ms`。detached bash 仍默认无截止时间，并在停止、取消或退出时清理进程组。

这三项 Codex 开关也可写入 `$NIB_HOME/config.toml` 的 `[codex]` 段，环境变量优先。详见 [配置](https://github.com/yyydddkkk/nib-code/blob/v0.4.0/docs/config.md) 与 [Codex](https://github.com/yyydddkkk/nib-code/blob/v0.4.0/docs/codex.md)。

## 长任务与验证

- **长 Run 自动转后台**：默认等待工具超过 10 秒后，模型先收到任务通知，原脚本和 await 继续执行，最终输出自动送达。没有独立工作时 Session 在本地等待，不反复请求模型；`[limits].run_background_after_ms` 可调整阈值。
- **修改后直接重跑验证**：同 Session 通过 edit/write 修改文件后，重跑相同 command/cwd 会停止更早 Run 中仍活动的同一 bash。旧调用返回 `{superseded_by:"bN"}`，不表示通过或失败；脚本检查退出码前应处理该标记。detached、同 Run 内的并行调用及无修改的重复调用不受此机制影响。已有副作用不回滚。
- **显式停止需要理由**：`tools.stop({id, reason})` 的 reason 需非空白；停止未完成测试不等于验证通过。
- **委派提示减少串行等待**：默认由主循环修改、构建和测试；按任务需要使用独立调查、fork 或完成后的 resume。

后台 Run 与其他工作共享文件，没有工作区隔离；取代只停止匹配的 bash，原脚本仍可继续产生副作用。详见 [Run 生命周期](https://github.com/yyydddkkk/nib-code/blob/v0.4.0/docs/run-output.md#长-run-自动转后台) 和 [取代语义](https://github.com/yyydddkkk/nib-code/blob/v0.4.0/docs/tool-delegation.md#同一命令取代过时执行)。

## 输出、诊断与兼容

- Run 展示预算可通过 `[limits].run_output_bytes` / `NIB_RUN_OUTPUT_BYTES` 调整，默认仍为 16 KiB；工具交给 JS 的数据保持完整，console 捕获上限仍为 64 KiB。离线 replay 使用录制时预算。
- 模型请求分别限制字节空闲（300 秒）、内容空闲（120 秒）和单次尝试总时长（300 秒），均可配置；每次重试重新计时，整个 Step 可更长。合法长推理可能需要调高限额。
- 日志保留有序 Responses 输出、逐次请求诊断、传输降级原因、后台实际执行区间和 bash 启动/取代事件，便于区分模型等待与工具执行。
- 修复传输降级或缺失 previous response 后的会话恢复及离线 replay：独立诊断记录不再被当作历史替换。
- 旧会话继续使用原 system；custom/function 历史和旧录制仍可恢复、重放。新版脚本错误诊断可能造成旧 replay 展示差异；新日志不保证能被旧二进制读取。分享日志时检查完整命令和 calls 旁路中的敏感内容。

## 回退配置示例

```sh
NIB_CODEX_TRANSPORT=sse NIB_CODEX_RUN_TOOL=function NIB_REASONING_SUMMARY=auto nib
```

这些开关只调整后续请求，不改写已有历史。ReleaseFast 构建方式仍为 `zig build -Doptimize=ReleaseFast`。
