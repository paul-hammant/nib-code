# ask NDJSON interface

`nib ask --json '<prompt>'` writes NDJSON to stdout: one single-key object per line, emitted in order and flushed immediately. stderr has no human-readable progress or color. Prompt - reads stdin through EOF, also in ordinary ask. Exit 0 on success, nonzero on failure.

- {"start":{"session_id":"<32-character-lowercase-hex>"}}: Session initialized; resume keeps its id.
- {"step":{"n":3,"effort":"low"}}: before each main-model Step request. n starts at 1 per Turn; effort is the actual request level, or default when no server level is specified. Retries do not repeat events; compaction emits none. Subsequent `run_start/run_end` belong to this Step until the next step event. Ordinary ask hides it; TUI retains metadata but default Run titles hide effort.
- {"delta":{"kind":"text|reasoning","text":"..."}}: streamed fragments including intermediate-Step text. With pending ordinary background results, buffer text until response completion: tool-bearing replies emit deltas; tool-free waiting replies become notices without text deltas. Final answers still come only from end.text.
- {"`run_start`":"`<JS-code>`"}, `{"run_end":{"ok":true,"output":"...","changes":[...],"tool_summary":{"counts":[{"name":"read","count":2},{"name":"bash","count":1}],"omitted":0,"files":[{"tool":"read","path":"src/a.zig"}]}}}`: Run start/result. `run_start` stays a string without effort; use the preceding step event for producing-request effort. Models may handle Run failures. changes accumulates successful edit/write: path/added/removed/created/diff. Compare immediate before/after per successful operation, sum added/removed by path, OR created, preserve first-path order. Not net Run-start/end diffs; reverted edits count both directions. Failed calls add nothing, but later Run failure does not erase earlier successes. Concatenate diff operations in order with one context line, + / - / space prefixes, separated by …; cap each path at 200 change/context lines per Run, excluding omission markers. Preview limits do not alter counts. No Run-end disk reread; bash/external/child/background changes between/after writes do not count, though later edit/write may show them as unchanged context. `tool_summary` counts actually dispatched host calls in first-dispatch name order, including errors after dispatch, excluding admission rejection (e.g. excess llm), child-internal calls, or source inference. Step timing retains at most 200 calls; omitted counts this Run's overflow, unassignable to names, so counts are incomplete on overflow. Unretained admission rejections may also enter omitted. Normal `run_end` always includes the object, even {"counts":[],"omitted":0,"files":[]}; absent optional fields in old events mean unavailable, not zero calls. files deduplicates dispatched read/grep/glob {tool,path} in first-dispatch order; old logs may omit. UI paths only: no change to tool returns or model input.
- {"progress":{"id":"a1","background":false,"kind":"agent","run":1,"prompt":"Check tests","state":"working","step":3,"tools":["edit"],"files":["src/x.zig"],"usage":{"prompt_tokens":41000,"completion_tokens":200,"prompt_cache_hit_tokens":32000}}}: latest task snapshot. Session task ids share a1,a2… for foreground/background agents and independent b1,b2… for bash, never resetting across Runs/Turns; resume continues each prefix maximum. background identifies tasks with matching start return/background events/results; old agent/background_id fields are gone. detached defaults false and marks bash not awaited by normal Turns. run is the 1-based Session initiating Run, including `/js`, associating progress with originals. kind agent|bash; bash prompt is the full command, `elapsed_ms` its duration. All bash gets ids at start; foreground progress appears after 3 seconds, then roughly every second; all endings emit terminal progress, normal exits with exit_code. Agent prompt is full task text; state `queued|working|done|failed|canceled|timed_out` maps in TUI to running/completed/timed out where applicable. Finished-but-undelivered tasks show waiting, known failure/timeout immediately; detached is marked separately. step starts at 1, or 0 before model activity. tools deduplicates `tools.<name>(...)` identified in latest `run_start` source; files comes from that `run_end.changes`, cleared at new Run start. usage is cumulative child-reported usage; display prompt+completion without recounting cache, not deltas or extra parent usage. Ordinary events are at least a second apart, intermediate states merged, terminal states unthrottled. Final results/usage follow `run_end` and end/error. Ordinary ask hides progress. Continuations keep task ids. invocation distinguishes calls with the same id internally; it is neither task id nor `tools.agent` argument/result/tree text. 0 means unassigned; resume does not retain the sequence.
- {"background":{"id":"a1","kind":"agent","state":"started"}}, {"background":{"id":"b2","kind":"bash","state":"finished","ok":true}}: background lifecycles, using separate a/b counters matching progress ids. started follows synchronous pre-start log persistence; finished occurs on result insertion; resume emits lost for unfinished tasks. Only finished carries ok; no result body. Ordinary ask hides events.
- `{"usage":{"prompt_tokens":0,"completion_tokens":0,"prompt_cache_hit_tokens":0}}`: cumulative Turn snapshot, including reported child usage, not a delta; supports live display and forced-termination accounting.
- `{"retry":{"attempt":1,"delay_ms":1000,"reason":"..."}}`, {"notice":"..."}: retries/notices.
- {"end":{"text":"`<final-answer>`","usage":{"prompt_tokens":0,"completion_tokens":0,"prompt_cache_hit_tokens":0},"steps":1}}: successful Turn; usage covers this Turn including automatic compaction/children. Use text here, not concatenated deltas.
- `{"error":{"message":"...","usage":{"prompt_tokens":0,"completion_tokens":0,"prompt_cache_hit_tokens":0},"steps":0}}`: command/Turn failure, no end; initialization failure may omit start. Retain reported usage/steps. Error text is diagnostic, not a stable code.

`end/error` may also include timing: {`wall_ms`, `model_ms`, `run_ms`, `llm_calls`, `agent_calls`, `tool_bytes`, `output_bytes`}. Always present once Turn execution starts; absent for parsing/initialization failures before then. `wall_ms` is whole-Turn monotonic time including pre-failure/cancellation waits, compaction, cleanup. model_ms/run_ms sum same-named fields from committed complete Steps, excluding unfinished Steps. llm_calls/agent_calls count actually dispatched host calls in those Steps, including errors, excluding child-internal calls, independent of the 200-call log cap. tool_bytes/output_bytes similarly sum committed Step fields: host→JS result UTF-8 bytes (serialized JSON success, error text failure) versus formatted model tool-result UTF-8 bytes (including truncation/error/no-output notices/labels), plus newly inserted background agent/bash result-message bodies before complete-Step requests (including prefixes/newlines/markers, excluding interjections and historical recounting). Exclude unfinished Steps; agent counts parent returned objects only, not child-internal data. Matches TurnSummary.timing. Durations are ms; retain zero byte/call keys. Existing `usage/steps` remain unchanged and may include reported unfinished-Step usage on failure. Ordinary ask omits timings; internal `turn_end` snapshots are not extra NDJSON events.

Events/serialization: src/session/events.zig. JSON-escaped newlines keep every physical line complete JSON.

Commit/cancellation: [session-log.md](session-log.md); child calls: [tool-delegation.md](tool-delegation.md).

Automatic background Runs use `background.kind:"run"` and rN ids. Early `run_end` output is registration notification, changes empty, ok confirms notification only. Final `background.state:"finished"` completion includes original step/run_index, actual ok, output within configured budget (default 16 KiB), complete run_ms/tool_bytes/calls/calls_omitted/changes and execution interval. No second run_end. Fields/measurement: [session-log.md](session-log.md#automatic-background-run-recording-and-statistics).

Finished background bash may carry `execution:{start_ms_epoch,end_ms_epoch}` (Unix ms, before spawn through wait completion), ending no later than result delivery; omit if spawn fails. Automatic Run completion.execution starts at original Run creation, including pre-background waits.

TUI recovery notices never enter ask output. Automatically backgrounded `run_end` may carry `background_id` (e.g. r3); `ok:true` means registered only, final status comes from background results. Bash progress may carry `superseded_by`, a neutral state. `output_bytes` reflects observed command output progress, distinguishing actual output from timing heartbeats.

Usage may include `prompt_cache_write_tokens` (cache-creation input). Omit zero, read missing as zero; prompt_tokens already includes these inputs, so do not recount in totals. Other fields remain unchanged.
