# One Provider interface, two wire protocols

**Decision:** `src/provider.zig` defines Config, Message, Reply, Usage, and stream, internally selecting Chat Completions (original DeepSeek/OpenAI-compatible transport) or Codex Responses. `src/config.zig` parses `$NIB_HOME/config.toml` (default `~/.nib/config.toml`) and environment overrides; CLI then applies effort. Agent, summaries, and children share the interface/effective configuration. Codex is default; Chat Completions still supports DeepSeek. Configuration, instructions, and Sessions share NIB_HOME, without XDG reads/migration; see [configuration](../config.md).

At runtime Codex reads `tokens.access_token/account_id` from `$CODEX_HOME/auth.json` (default `~/.codex/auth.json`) and sends to https://chatgpt.com/backend-api/codex/responses. Headers: Authorization, chatgpt-account-id, OpenAI-Beta, originator; body uses instructions, store:false, streaming input, include:["reasoning.encrypted_content"]. On 401 reread once and retry once; repeat failure asks for codex login. No OAuth or shared refresh_token refresh/rotation/storage. Authentication errors expose no response bodies or credential parsing content.

Message reasoning is provider-tagged continuation data: raw reasoning_content for Chat Completions, JSON of complete reasoning items including encrypted_content for Responses. Resume extracts readable summaries, hiding ciphertext; assistant phase persists too. Codex defaults to custom run (Lark grammar, direct JS input), configurable function fallback; Chat Completions keeps function. Old function history stays unchanged; results pair by type, without converting history for current definitions. Internal custom uses `type:"custom"` plus normalized {code} to reuse Session/log/replay; effort uses optional first line // @run: {"effort":"low"}. See [custom Run decision](0018-custom-run.md). Use complete output_item.done arguments, never unfinished arguments. Commit Steps only on completed; incomplete/failed/truncated responses retry or error by classification, preserving server code/message. Codex may retry after deltas; failed partials are not committed. Unretried/exhausted failures append independent diagnostics only, outside model history. See [Codex usage](../codex.md#stream-failures-and-retries) for classification/backoff/diagnostics. Both protocols map to existing Usage, including cache hits.

Headers store provider/model; each commit records its model. Cross-provider resume rejects without history conversion; Codex also rejects model changes to protect encrypted reasoning. Chat Completions uses the current configured model. Missing provider in old logs means Chat Completions; legacy reasoning_content migrates during replay without rewriting files.

**Configuration and summaries:** Codex defaults to `gpt-6.1-sol`, window 500,000; model/window come from pi, see [Codex](../codex.md). NIB_THINKING=on uses medium absent effort; off overrides NIB_REASONING_EFFORT, mapping to none where supported or low for pi's non-disableable sol/astra. Without environment reasoning overrides, use file effort, otherwise server defaults. Explicit CLI effort overrides environment/files without persistence. TUI `/effort` atomically saves top-level effort, preserving other lines; default deletes it. Summaries always use the current Session model to preserve cache prefixes and avoid encrypted reasoning across models, disabling reasoning where possible, otherwise low.

Codex summaries do not retain the old 32–2048-token total-output limit: like pi, omit max_output_tokens for normal server allowance, specifying the text budget separately in prompts to leave reasoning room. pi catalog maxTokens 128000 is not a client-guaranteed hard limit; server decides actual allowance. Empty/truncated/ineffective summaries follow [0007](0007-context-compaction.md): automatic notice/continue, manual error, history unchanged.

Children receive prompt/effective Config through anonymous stdin pipes and skip config-file reads; no API keys through argv/environment. Codex Config api_key is empty; each process reads its login file independently. Secret environment removal/credential-path rejection: [0006](0006-deny-dangerous-commands.md).

**WebSocket:** Since 0.4.0 Codex defaults to WS, retaining explicit SSE and Session fallback. Exclusive connections, disposable state, and ordered-history tradeoffs: [0017](0017-codex-websocket.md); protocol/limits: [Codex transport](../codex.md#responses-websocket-transport).

**Why:** Protocol implementations handle serialization, reasoning continuation, authentication, and event differences; Session remains protocol-agnostic. Reuse logs/tool models without OAuth lifecycle, model-discovery services, or another Session store.

**Evidence and boundaries (2026-11-01):** Primary local pi sources: `packages/ai/src/api/openai-codex-responses.ts`, `openai-responses-shared.ts`, `catalog/providers/openai-codex.ts`, catalog/families/openai.ts. [OpenAI Responses item docs](https://developers.openai.com/api/reference/resources/conversations/subresources/items/methods/create) describe output_item.done encrypted_content for stateless continuation. Local mocks verify headers, text, tools, two reasoning items, multi-Turn resume, summaries, children, usage, 401, credential isolation. Model lists are source snapshots, not account availability guarantees; unknown models require explicit `context_window` or NIB_CONTEXT_WINDOW.

**Verification (2026-11-01):** zig build test --summary all passed 62/62; `tests/test_session.py`, `tests/test_codex.py`, and ReleaseFast build passed. Additional mock coverage: encrypted items over 100KB, assistant phase, same-model low summaries, continuation after empty/truncated summaries, cross-model rejection. A real ReleaseFast request from an empty temporary directory, isolating global/project instructions and excluding repository contents, sent “Hello.” and received “Hello! How can I help you?” from `gpt-6.1-sol`: 1 Step, 479 input/13 output tokens, no Run, empty stderr. No extra real-service calls for tools, long Sessions, or compaction; those use mocks.

**When to reconsider:** Three protocols/data-driven services follow in [0020](0020-providers.md); backend/window changes or real needs for cross-provider history conversion, OAuth, server compaction.
